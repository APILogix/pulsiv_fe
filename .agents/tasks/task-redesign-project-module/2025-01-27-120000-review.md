# Modern UI redesign across 20+ project module pages

This change rewrites the UI of every page in the project module: listing, creation wizard, overview, analytics, environments, API keys, settings, thresholds, alert channels/routes, connectors, members, usage, activity, delivery logs, dead letter queue, remote config, and member alert preferences. The existing Sentinel design system tokens (`var(--brand)`, `var(--bg1)`, etc.) are preserved throughout. The approach layers visual polish — gradient fills, hover tooltips, skeleton loading, subtle animations, colored accent bars, monogram avatars, timeline connectors — on top of the same React component architecture and data hooks. Pages that previously used the old `FillPage`/`InfiniteTable` observe primitives (AlertDeliveryLogs, DeadLetterQueue, RemoteConfig) are fully migrated to the modern pulse primitives (`Panel`, `SectionHeading`, `StatCard`, `Pill`, `Table`).

**Watch for:** Direct DOM access via `document.getElementById` to reset the search input (confirmed); `useMemo` with `Date.now()` is redundant under React 19 compiler and semantically misleading (confirmed); `ThresholdGauge` renders a hardcoded 65% position for every threshold regardless of actual metric values (confirmed); AlertRouteWizard in edit mode never hydrates form state from fetched data (confirmed).

## High-level view

The project listing page gains debounced real-time search, a grid/list view toggle, skeleton loading, and enhanced project cards with hover effects. The CreateProjectWizard converts from a single-submit form to a three-step wizard with controlled inputs, live slug preview, and a summary confirmation step.

The analytics page adds interactive SVG chart behavior: crosshair line, hover dots, and a floating tooltip. The heatmap cells gain hover-reveal tooltips. A sticky toolbar keeps the date range visible during scroll.

Environment, API key, threshold, alert channel, connector, and member pages receive accent-color visual treatments and richer empty states. The environments page now fetches API key counts (additional network call with a hardcoded limit of 500). The API keys page adds a health-indicator dot per key and an "at a glance" strip.

The activity page groups events by time period with sticky section headers and a vertical timeline connector. The dead letter queue and alert delivery logs are rewritten from `InfiniteTable` to pulse `Table` with confirm dialogs for destructive actions.

## Debounced search and DOM escape hatch in ProjectsPage

The "Clear filters" button resets the search input via:

```tsx
const input = document.getElementById("project-search") as HTMLInputElement | null;
if (input) input.value = "";
```

Since the input uses `defaultValue` (uncontrolled), React doesn't track its value. This escape hatch fails silently if the element id changes and creates an ordering dependency between the state reset (`setSearch("")`) and the DOM mutation. A `useRef<HTMLInputElement>` attached to the input solves this within React's model.

## `useMemo` and `Date.now()` in ProjectApiKeysPage

```tsx
const avgAgeDays = useMemo(() => {
  const activeKeys = keys.filter((k) => k.status === "active" && k.createdAt);
  if (activeKeys.length === 0) return 0;
  const total = activeKeys.reduce((sum, k) => sum + (Date.now() - new Date(k.createdAt).getTime()), 0);
  return Math.round(total / activeKeys.length / (1000 * 60 * 60 * 24));
}, [keys]);
```

The dependency array is `[keys]` but the computation calls `Date.now()` — the "average age" only updates when the key list reference changes, not as real time passes. Under React 19 compiler, `useMemo` is compiled away anyway. This should be a plain derived value.

## ThresholdGauge renders decorative fiction

```tsx
const position = 65; // threshold marker position (percentage along bar)
```

Every threshold renders its gauge marker at the same fixed 65% position. Without a real metric value to compare against the threshold, this gauge conveys no actionable information and may mislead users into thinking their metric sits at some specific point. Either accept a `currentValue` prop from telemetry or remove the component.

## AlertRouteWizard edit-mode hydration gap

```tsx
const [name, setName] = useState("");
const [description, setDescription] = useState("");
```

`useAlertRoute` fetches existing route data, but nothing writes `routeData` into these state variables once it resolves. Opening an existing route for editing shows blank fields. The wizard's controlled inputs make hydration straightforward via an effect keyed on `routeData`.

## Unhandled async errors in DLQ per-row actions

```tsx
<DropdownMenuItem
  onClick={async () => {
    await mutations.reprocessDeadLetter.mutateAsync(String(item.id));
    toast.success("Replayed successfully");
  }}
>
```

If `mutateAsync` rejects, the error propagates as an unhandled promise rejection. The page-level purge/replay-all actions use `ConfirmDialog` with proper error handling, but the per-row actions do not. Wrap in try/catch with a `toast.error` fallback — this is an asymmetry between bulk and individual destructive actions.

## Activity page time-grouping instability

`getTimeGroup` calls `new Date()` on every invocation. Because the grouping runs on each render (including when a user expands a row detail), boundary conditions can shift mid-session — a message at 23:59 could flip from "Today" to "Yesterday" on re-render. Capture `Date.now()` once per render cycle and pass it to the grouping function.

## Environments page key-count fetch with hardcoded limit

`useApiKeys(projectId, { includeInactive: true, limit: 500 })` fetches all keys just to count them per environment. Projects with more than 500 keys will show undercounted results. If the API supports a grouped-count endpoint, prefer that. Otherwise, at minimum document or raise the limit.
